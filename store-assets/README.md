# Chrome Web Store listing assets

Generated by `npm run store:assets` — do not hand-edit.
Regenerate after any UI change so the listing does not drift from the product.

| File | Size | Required by the store |
|---|---|---|
| `screenshot-1-explain.png` | 1280x800 | Yes — at least one screenshot |
| `screenshot-2-lenses.png` | 1280x800 | No — up to 5 allowed |
| `screenshot-3-chat.png` | 1280x800 | No — up to 5 allowed |
| `screenshot-4-memory.png` | 1280x800 | No — up to 5 allowed |
| `promo-small-440x280.png` | 440x280 | Yes |
| `promo-marquee-1400x560.png` | 1400x560 | No — for store featuring |

The in-page shots compose the extension's shipped stylesheet and DOM structure over
a mock article; the memory shot does the same with the options stylesheets. They are
not captures of a live session: on the mock runtime a live capture would show the
"sample answer" banner, and a real runtime needs an API key. Everything visual comes
from `extension/content/styles.css` and `extension/options/`, so these go stale when
the UI does — regenerate rather than retouch.
